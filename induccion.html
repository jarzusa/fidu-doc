Sistema de Rutas
RBAC, versionamiento y lazy loading
ℹ️
Los permisos de cada ruta se validan contra la respuesta del login API. El campo requiredValidRole.view debe coincidir exactamente con el child.identifier que devuelve el backend.

Patrón de ruta con RBAC

typescript — src/router/treasury/checkbooks.ts 
export default [
  {
    path: '/tesoreria/chequeras',
    name: 'CheckbooksList',        // PascalCase — igual al identifier del login
    component: () => import('@/views/treasury/checkbooks/v1/list/CheckbooksList.vue'),
    meta: {
      requiresAuth: true,
      requiresFirstPasswordChanged: true,
      requiredValidRole: {
        module: 'Treasury',        // Clave del módulo en la respuesta del login
        view: 'CheckbooksList',    // Coincide con child.identifier del login
        action: 'list'             // 'list'|'create'|'edit'|'delete'|'view'|'export'…
      },
    },
  },
]

Stores Pinia — Reglas Estrictas
TDZ, versioning, state mínimo y métodos HTTP
🚨
El store NO almacena listas, paginación, forms ni responses. Las actions retornan los datos directamente. El state solo tiene lo que se comparte entre múltiples componentes o persiste entre navegaciones. Referencia: src/stores/accounting/cost-centers/cost-center-v3.ts
❌ Patrón antiguo — no usar
typescript
state: () => ({
  // ❌ Listas paginadas en state
  data_list: [] as ICheckbookResponse[],
  data_pages: { currentPage: 0, lastPage: 0 },
  // ❌ Forms temporales en state
  data_information_form: null,
  // ❌ Respuestas getById en state
  data_response: null,
})
✅ Patrón moderno — cost-center-v3.ts
typescript
state: () => ({
  version: 'v3',  // Solo lo compartido/persistente
}),
actions: {
  async _getListAction(params) {
    let responseList: IPaginated<ICostCenterListItem> | null
      = { list: [], pages: { currentPage: 0, lastPage: 0 } }

    await executeApi()
      .get(URL_PATH, { params: { ...params, paginate: 1 } })
      .then(({ data: { data: { data: items, current_page, last_page }, message, success } }) => {
        responseList = { list: items, pages: { currentPage: current_page, lastPage: last_page } }
        showAlert(message, success ? 'success' : 'error', undefined, TIMEOUT_ALERT)
      })
      .catch(e => showAlert(showCatchError(e), 'error', undefined, TIMEOUT_ALERT))

    return responseList  // ← View composable recibe y guarda en ref local
  },
}
❌ Barrel import → TDZ en producción
typescript
// Genera chunk circular → TDZ error
import { useAlert, useShowError, useUtils }
  from '@/composables'

// Fuera de defineStore → TDZ
const { showAlert } = useAlert()
export const useMyStore = defineStore(...)
✅ Imports directos + dentro de actions
typescript
// Imports directos — rompen el ciclo
import { useAlert } from '@/composables/useAlert'
import { useShowError } from '@/composables/useShowError'

export const useMyStore = defineStore('my-store', {
  actions: {
    async _createX(payload) {
      // Dentro de la action — correcto
      const { showAlert } = useAlert()
      const { showCatchError } = useShowError()
    }
  }
})
typescript — src/stores/treasury/checkbooks/index.ts
export const useCheckbooksStore = (version: 'v1' | 'v2' = 'v1') => {
  switch (version) {
    case 'v1': return useCheckbooksStoreV1()
    case 'v2': return useCheckbooksStoreV2()
    default:   return useCheckbooksStoreV1()
  }
}
⚠️
Regla de versiones: Si existen v1, v2 y v5 → v2 es la estable legacy, v5 es la nueva pendiente de QA. Una vez v5 pasa QA → eliminar v2 completamente (store + views + Forms asociados). Nunca acumular versiones muertas.
Prefijo de actionMétodo HTTP obligatorioEjemplo
_getX / _getListAction.get()_getListAction → .get()
_createX.post()_createCheckbook → .post()
_updateX.put() / .patch()_updateCheckbook → .put()
_deleteX.delete()_deleteCheckbook → .delete()
🚨
Un _deleteX que llame .put() es un bug funcional, no un problema de estilo.

Iconos — Solo Lucide
defaultIconsLucide de useUtils() — nunca strings MDI
🚨
Lucide Vue Next es la ÚNICA fuente de iconos. Strings MDI ('mdi-plus') están prohibidos en features de negocio. Los iconos se obtienen en el view composable, nunca en el store.
❌ Incorrecto
typescript
// ❌ Strings MDI
icon: 'mdi-plus-circle-outline'

// ❌ useUtils en state() del store → TDZ CRASH
state: () => ({
  btn: { icon: useUtils().defaultIconsLucide.plusCircle }
})

// ❌ A nivel de módulo → TDZ
const { defaultIconsLucide } = useUtils()
export const useMyStore = defineStore(...)
✅ Correcto — en el view composable
typescript
// En el view composable (.ts) — no en el store
const { defaultIconsLucide } = useUtils()

const icons = {
  add:      defaultIconsLucide.plusCircle,
  edit:     defaultIconsLucide.pencil,
  delete:   defaultIconsLucide.trash2,
  view:     defaultIconsLucide.eye,
  download: defaultIconsLucide.download,
}

// En template:

<ContentComponent :btn-icon="icons.add" />

Flujo Completo de una Feature
End-to-End — desde la ruta hasta el DELETE
1
Usuario entra a /tesoreria/chequeras
Router beforeEach: valida token ✓ → valida Treasury.CheckbooksList.list ✓
2
CheckbooksList.vue carga

3
Usuario filtra → handleFilter → listAction

4
Click "Crear" → CheckbooksCreate.vue
Guard valida action='create' ✓. InformationForm con action="create"
5
Submit: validateForm → _createCheckbook → POST
executeApi().post(URL_PATH, payload) → retorna boolean → router.push('CheckbooksList')
6
Click "Editar" → CheckbooksEdit.vue
_getByStructureId(id) retorna ICheckbookResponse | null. InformationForm con action="edit" :data="currentCheckbook"
7
Click "Eliminar" → AlertModal → DELETE
alertModalRef.value.openModal() → confirm → _deleteCheckbook(id) → .delete() → refrescar lista
